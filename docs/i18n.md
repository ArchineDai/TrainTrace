# 国际化

ARB + `flutter gen-l10n`，机制照搬 weluck（D:\dev\app，`docs/i18n.md`），按本项目
离线、Drift 存设置的现状做了几处改动（见文末）。配置在 [l10n.yaml](../l10n.yaml)：

```yaml
arb-dir: lib/l10n
template-arb-file: app_zh.arb        # 模板是 zh：文案先用中文写，英文是译文
output-localization-file: app_localizations.dart
output-dir: lib/l10n
nullable-getter: false               # AppLocalizations.of(context) 非空，不写 !
untranslated-messages-file: l10n_untranslated.json
```

`pubspec.yaml` 里 `flutter: generate: true`，`flutter build` / `flutter run` 会自动跑
gen-l10n。改完 ARB **必跑 `scripts/check_l10n.ps1`**（内含 gen-l10n），它才会告诉你
漏了翻译。生成码 `lib/l10n/app_localizations*.dart` **在 git 追踪中，需要提交**。

## 支持的语言

| code | 标签 | ARB |
|---|---|---|
| `zh` | 中文 | `app_zh.arb`（**模板**） |
| `en` | English | `app_en.arb` |

### 语言选择：跟随系统，回落 `zh`

设置 → 语言的列表首行是**跟随系统**（`followSystemLanguage`），对齐 Android/iOS 的
应用内语言设置。选它就是"没有选择"：

用户在设置里选过语言就以存储为准；**没选过则按设备的语言偏好顺序取第一个我们支持的，
都不支持时回落 `zh`**（`LocaleSettingsViewModel.resolveDefaultLocale`）。回落 `zh` 而不是
`en`：产品面向国内用户，且没有服务端要对齐（weluck 回落 `en` 是为了和接口的
`Accept-Language` 默认值一致）。

跟随系统是**动态**的：解析结果不落盘（`writeLocale(null)` 是删行，不写 `'system'`
之类的哨兵值），用户没显式选过就一直跟着设备走；一旦在设置里选过，存储值永远优先。
系统语言在 App 运行期间变化时，`app.dart` 的 `didChangeLocales` 调 `refreshFromDevice()`
重算，不必重启；显式选过语言的用户不受影响（判断在 notifier 里）。

**`localeSettingsProvider` 的 state 是 `({String? selected, Locale effective})`，两个字段
不能合并**：`selected` 为 null 表示跟随系统，设置页的勾选判它；`effective` 是解析后的
生效值，`MaterialApp.locale` 用它。合成一个字段的话，跟随系统时勾会打到解析出来的那门
语言上，用户再也回不到"跟随系统" —— 单向门，而且不报错。

存储：`app_settings` 表的 `locale` 键，经 `SettingsRepository.readLocale / writeLocale`。
库里是不认识的语言码（某门语言后来被移除）时 ViewModel 当作没选过，不抛错、不改库。
`main()` 在首帧前 `await localeSettingsProvider.future`，冷启动不会先按设备语言渲染
一帧再跳到用户选的语言。

### 加新语言要改两处

1. `lib/l10n/app_<code>.arb` —— 新文件，**从 `app_zh.arb` 全量复制后翻译**
   （非模板 ARB 不需要 `@` 元数据块）
2. `locale_settings_view_model.dart` 的 `localeOptions` 常量（含设置页展示用的 `label`，
   用该语言的自称）

漏了第 2 处不会报错，只是设置页里选不到 —— 所以
`test/state/locale_settings_view_model_test.dart` 守着"`localeOptions` 与
`AppLocalizations.supportedLocales` 一一对应"。

`app.dart` 的 `supportedLocales` **不用改** —— 它读 ARB 生成的
`AppLocalizations.supportedLocales`，首启默认语言的解析读的也是同一份。两处各抄一份
的话，解析结果和 MaterialApp 支持列表对不上时会静默回落到空翻译。

## 漏翻检测：`scripts/check_l10n.ps1`

**`gen-l10n` 对缺失 key 只发 warning，不报错。** 缺的 key 静默回落到模板（中文），
英文用户会在某个按钮上看到一句中文，而 analyze / test 全绿。

```bash
pwsh scripts/check_l10n.ps1
```

内部跑 `flutter gen-l10n`，把 `l10n_untranslated.json`（已 gitignore）里各 locale 的
缺失数跟 `scripts/l10n_baseline.json` 比对。基线是棘轮：只在**超出**基线时 exit 1，
存量欠债照旧打印但不阻断；补完译文后 `-Update` 收紧，只降不升。当前基线为空 ——
**任何 locale 漏一个 key 就红**。

ARB 语法错、key 不是合法 Dart 标识符（不能以下划线开头）时 gen-l10n 本身非零退出，
脚本同样红，不会因为"没产出报告"就当成没缺失。

## 工作流

改文案请用 `/add-text` skill（`.claude/skills/add-text`）。手工做的话：

1. 改 `lib/l10n/app_zh.arb`（模板，key 的唯一定义处）
2. **同步 `app_en.arb`** —— 不确定译法就先写中文原文占位，并在回复里标注待翻译；
   留空或跳过会变成静默回落，比标注出来更糟
3. `pwsh scripts/check_l10n.ps1`，看到 `OK`
4. 提交生成码 `lib/l10n/app_localizations*.dart`

key 用 camelCase，语义命名而非位置命名（`workoutAlwaysDark` 而不是 `settingsRow2`），
插在语义相邻的现有 key 附近。带变量的用 ICU 占位符，模板里**必须**带 `@key` 元数据：

```json
"placeholderPending": "{phase} 接入",
"@placeholderPending": {
  "placeholders": { "phase": { "type": "String" } }
}
```

### 页面里取值

```dart
import '../../../l10n/app_localizations.dart';

final l10n = AppLocalizations.of(context);   // 非空，不写 !
Text(l10n.settings)
Text(l10n.placeholderPending(phase))          // 带占位符的是方法调用
```

### 没有 `BuildContext` 的地方

三条路子，落地位置都已固定：

1. **枚举展示名 → presentation 层扩展**。model 里不存中文串。
   - `MuscleGroup` / `EquipmentType` → `features/exercises/presentation/exercise_labels.dart`
     的 `label(AppLocalizations l10n)`
   - `SetType` → `features/workout/presentation/widgets/set_type_labels.dart`
2. **纯函数收一个 `AppLocalizations` 参数**，调用方在有 context 的地方取好传进去。
   - `Formatters.relativeDay / monthLabel / dateTime / duration`（`kg` / `clock` /
     `setsSummary` 与语言无关，不收）
   - `SuggestionEngine.evaluate(input, l10n)` —— 建议的 title / reason / nextTarget
     是拼好的成品串，`Suggestion` 仍是纯数据 model
3. **服务层与 provider 里的纯计算 → `appLocalizationsProvider`**
   （`features/settings/state/app_localizations_provider.dart`）。它按
   `localeSettingsProvider` 的 `effective` 做 `lookupAppLocalizations`，`watch` 它的
   provider 在用户改语言时会重算。
   - 休息提醒：`RestNotifier.scheduleRestEnd(at, text: RestNotificationText(...))`，
     服务层不 import l10n。**注意 Android 通知渠道只在首次创建时取名**，之后换语言
     不会重命名已存在的渠道 —— 平台限制。
   - `suggestionProvider` 从它取 l10n 再喂给引擎。

**有 context 就用 `AppLocalizations.of(context)`**，别绕 provider。

### 动作名不进 ARB

种子动作在 `assets/seed/exercises.json` 里已带 `nameZh` / `nameEn`，展示时按当前语言
选字段：`features/exercises/presentation/exercise_labels.dart` 的
`exerciseDisplayName(context, nameZh, nameEn)`（`Exercise` 上还有
`displayName(context)` / `alternateName(context)` 两个扩展）。

repository join 出来的展示字段（`WorkoutExercise` / `RoutineExercise` 的
`exerciseName` / `exerciseNameEn`）**都是可空的**：两个都为 null 表示 join 不到动作行
（动作被删了），`exerciseDisplayName` 回落到 `deletedExercise`。data 层不再自己拼
"（已删除的动作）"这种中文串。

用户自己输入的内容（模板名、器械备注、场馆名）来自数据库，不进 ARB、不翻译。

## 与 weluck 的差异

| 项 | weluck | TrainTrace | 原因 |
|---|---|---|---|
| 模板语言 / 回落 | `en` / `en` | `zh` / `zh` | 国内产品；无服务端要对齐 |
| 存储 | SharedPreferences（同步） | `app_settings`（Drift，异步） | 项目只有一个本地存储 |
| provider 形态 | `Notifier`，先落盘再改 state | `AsyncNotifier`，先改内存再写库 | 无 `Accept-Language` 拦截器要先读到新值；对齐 `themeSettingsProvider` |
| `AppLocalizations.of` | 可空，调用处 `!` | `nullable-getter: false` | 新项目没有历史包袱 |
| 远端文案覆盖层 | 有（`RemoteLocalizationsDelegate`） | 无 | V0.1 无网络；接服务端时再搬 `tool/gen_remote_l10n.dart` |
| 语言列表常量 | `List<Map<String, String>>` | `List<({String code, String label})>` | 记录类型有编译期字段检查 |

## 现状与欠债

**界面文案已全部走 l10n**（backlog D-11 完成）。`lib/` 里只剩两处硬编码中文，都是故意的：

- `features/dev/presentation/dev_playground_page.dart` —— 验证页，随 backlog D-6 整页删除
- `locale_settings_view_model.dart` 的 `localeOptions` 里的 `'中文'` —— 语言的自称，
  按设计就不该跟界面语言变

查缺口：`lib/` 下的 Dart 字符串字面量里出现汉字就是漏迁的（注释不算）。

欠债：`assets/seed/exercises.json` 的 `cues` / `commonMistakes` / `equipmentVariants`
只有中文，英文界面上这三段仍显示中文 —— 是内容缺口不是代码缺口，见 backlog D-16。
